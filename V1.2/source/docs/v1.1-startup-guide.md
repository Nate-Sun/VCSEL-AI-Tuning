# VCSEL AI Tuning V1.1 startup guide

`start-v1.1.ps1` starts the existing FastAPI backend and serves the production
React build from the same address. The launcher performs startup checks only;
it contains no optimizer, hardware write, authorization, or rollback logic.

## First build

Install dependencies separately according to the repository setup procedure.
The launcher never installs or upgrades packages. With dependencies already
available, build the frontend once from the repository root:

```powershell
pnpm --dir frontend build
```

If `frontend/dist/index.html` is absent, the launcher stops and prints that
same command.

## Safe default

From the repository root:

```powershell
.\start-v1.1.ps1
```

If the machine's PowerShell execution policy blocks `.ps1` files, use the
included one-click wrapper instead; it changes policy only for that child
process:

```powershell
.\start-v1.1.cmd -Mode FAKE
```

This is identical to:

```powershell
.\start-v1.1.ps1 -Mode FAKE
```

FAKE uses deterministic software adapters and does not connect to DCA, I2C, or
BERT. The default URL is `http://127.0.0.1:8000`; the browser opens after
`/health` succeeds and `/capabilities` confirms `runtime_mode=FAKE`.

The script uses its own location, so it can also be called from another folder:

```powershell
& "C:\path\to\VCSEL\start-v1.1.ps1" -Mode FAKE
```

Useful options:

```powershell
.\start-v1.1.ps1 -Mode FAKE -Port 8766
.\start-v1.1.ps1 -Mode FAKE -NoBrowser
.\start-v1.1.ps1 -Mode FAKE -ValidateOnly
```

`-ValidateOnly` checks Python, imports, frontend build, free port, and writable
runtime directories without starting FastAPI.

## Hardware-aware modes

READ_ONLY and LIVE_TUNING both require an explicit YAML file whose `mode`
matches the command:

```powershell
.\start-v1.1.ps1 -Mode READ_ONLY -ConfigPath C:\reviewed\runtime.yaml
.\start-v1.1.ps1 -Mode LIVE_TUNING -ConfigPath C:\reviewed\runtime.yaml
```

The files `runtime.read-only.example.yaml` and `runtime.live.example.yaml` are
non-runnable review templates: their endpoint fields are deliberate
`REVIEW_REQUIRED` placeholders. Do not point either mode at hardware until the
configuration, base setup, authority, B0 evidence, and rollback path have been
reviewed.

The launcher does not weaken backend restrictions. READ_ONLY continues to
reject mutation, and LIVE_TUNING still requires the normal backend preflight,
B0 freeze, authorization, readback, and rollback protections. Starting the
application never starts a Sweep or AI Tuning task by itself.

For READ_ONLY, `hardware.driver_profile` must be a reviewed
`LiveHardwareConfig` YAML. The DCA VISA resource, I2C COM port/address, and
BERT host/UDP port repeated in the runtime YAML must match the profile exactly.
The backend checks these values while assembling the runtime and fails before
hardware I/O on any mismatch.

The Outer ER SCPI fields in that profile are also matched against the built-in
query allowlist. A command that is not one of the audited `...?` readbacks, or
a DCA function that does not match the TDECQ `FUNCn` source, rejects assembly
before VISA is opened. READ_ONLY requires PAM4 mode and SSPRQ in both BERT
pattern fields.

READ_ONLY server import and startup do not open VISA, serial, or UDP resources.
Only an explicit V1.1 Preflight opens a bounded read-only session to capture a
fresh B0 from the configured DCA, I2C device, and BERT. That operation performs
identity and source/pattern readback only: it does not run or configure DCA
acquisition, write any tunable I2C register, call `setFir`, or write NLC. The
VD1124 bridge does emit audited page-select writes required for paged reads;
these are counted separately from tunable-register writes. All Sweep,
AI Optimization, and History Apply execution controls remain unavailable in
READ_ONLY.

The paged VD1124 read protocol records the page selected on entry, every
page-select frame and acknowledgement, and restores that same page in
`finally`, including when a read fails. It then reads the page register again;
an unverified restore rejects the capture and no B0 is produced. No tunable
register value is written.

## Python selection and logs

Python is selected in this order:

1. `VCSEL_AI_PYTHON`, when explicitly set;
2. `.venv-ai-tuning\Scripts\python.exe` beside the script;
3. the main repository virtual environment when running from `.worktrees`;
4. `python.exe` on `PATH`.

The selected interpreter must be Python 3.12 or newer with the project
dependencies already installed. Startup metadata and shutdown time are written
under `logs/v1.1-launcher-YYYYMMDD.log`.

Press `Ctrl+C` in the launcher window to stop the API. The launcher waits for
the child process and cleans it up before returning to PowerShell.

## Common failures

- **Frontend build missing:** run `pnpm --dir frontend build`; the launcher does
  not run an installer.
- **Port already in use:** choose another value, for example `-Port 8766`.
- **Runtime config missing or mode mismatch:** provide a real file whose
  top-level `mode` exactly matches `-Mode`.
- **Python import failure:** activate the intended environment or set
  `VCSEL_AI_PYTHON` to its `python.exe`.
