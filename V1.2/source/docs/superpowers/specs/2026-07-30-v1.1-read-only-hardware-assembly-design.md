# V1.1 READ_ONLY Hardware Assembly Design

## Problem

The launcher validates a complete `READ_ONLY` runtime document, but
`create_runtime()` rejects every non-FAKE runtime unless callers inject legacy
V1 adapter and tuning-profile factories. The official launcher deliberately
removes the external service-factory environment variable, so there is no
documented path from the reviewed runtime/profile YAML to a V1.1 gateway and
runner.

## Considered approaches

1. Keep requiring an external Python factory. This preserves the current
   architecture but leaves the official launcher unusable and moves the safety
   contract outside the reviewed repository.
2. Construct VISA, serial, and UDP clients while assembling the server. This
   is convenient but violates the requirement that import and startup perform
   no hardware access.
3. Add a built-in, lazily connected READ_ONLY gateway and a non-mutating
   runner. This keeps the reviewed YAML as the authority, creates connections
   only inside the explicit Preflight call, and exposes no mutation operation.

Approach 3 is selected.

## Configuration contract

For built-in READ_ONLY assembly, `hardware.driver_profile` points to an
existing `LiveHardwareConfig` YAML. Before any driver is constructed, assembly
loads that profile and requires exact equality for every endpoint duplicated
in the runtime YAML:

- DCA VISA resource;
- I2C COM port and device address;
- BERT host and UDP port.

The detailed profile remains authoritative for DCA function and expected IDN,
I2C baud/identity/register mapping, BERT local IP/port/channel, measurement
sources, and parameter fields. A mismatch fails closed before connection.
No endpoint is hard-coded or inferred.

Every profile-supplied DCA command must also exactly match the built-in
read-only query allowlist. DCA function and TDECQ `FUNCn` source must agree.
The BERT readback must identify PAM4 mode and SSPRQ in both pattern fields.

## Components

`vcsel_ai_tuning.v1_1.read_only_runtime` owns the production READ_ONLY path:

- `ReadOnlyDriverBundle` groups injected DCA query, I2C identity/readback, and
  BERT readback drivers for one bounded capture.
- `open_read_only_drivers()` defers imports and opens real drivers only while a
  Preflight capture is executing.
- `ReadOnlyV11Gateway` performs identity/configuration attestation and builds a
  single immutable `B0Snapshot` and `ParameterMapping` from the same capture.
- `ReadOnlyV11TaskRunner` rejects all execution/control methods and never owns
  hardware.

`create_runtime()` uses this built-in pair when mode is `READ_ONLY` and both
V1.1 components were omitted. An optional legacy external adapter/profile pair
affects only legacy V1 campaign assembly. `LIVE_TUNING` retains its current
explicit-factory requirement.
Legacy V1 campaign entry creation remains unavailable in the built-in V1.1
READ_ONLY path and fails before hardware access.

## Preflight data flow

Startup loads and cross-checks YAML only. Health/capabilities do not construct
drivers. An operator-initiated V1.1 hardware snapshot/Preflight enters the
existing hardware-authority fence and then:

1. opens a bounded driver bundle;
2. queries DCA `*IDN?`, ER source/units/status/details, and TDECQ
   source/status/details;
3. reads I2C chip ID/revision and every approved field/raw register;
4. reads BERT mode and the selected port/channel configuration, including
   both pattern fields, seven FIR taps, and Upper/Lower NLC;
5. rejects any identity, endpoint, source, units, status, channel, or SSPRQ
   mismatch;
6. creates the parameter mapping and one immutable dynamic B0 from those exact
   readbacks; and
7. closes every driver before returning the capture.

The I2C identity probe and field reader open the reviewed COM port
sequentially, so the Windows serial device is never opened by two clients at
once. Each bounded read saves and restores the entry page in `finally`.
Non-Preflight attestation and every runner operation fail before opening the
driver bundle.

The DCA interface used by this gateway exposes/query-calls only. The I2C path
uses `Vd1124Probe` and `Vd1124RegisterReader`, never the register writer. The
BERT path uses `GetMode` and `GetConfiguration`, never `setFir`.

## Evidence representation

The existing B0 schema is sufficient without migration:

- `HardwareIdentity.resource` records the exact VISA, COM/baud/address, or
  UDP/port/channel target;
- `HardwareIdentity.identity` records DCA IDN, I2C ID/revision, or BERT
  mode/two pattern fields;
- `DcaFingerprint.measurement_sources` records ER and TDECQ readbacks;
- `DcaFingerprint.configuration` records function, ER units/status/details,
  and TDECQ status/details;
- B0 fields hold all I2C decoded/raw values, FIR/NLC, SSPRQ, and mappings.

## Failure and safety behavior

All validation is fail-closed. Partial captures are discarded. No previous B0
is substituted. Startup, health, and capabilities never connect. READ_ONLY
runner methods reject every start/pause/resume/abort/recovery request. The
implementation does not add DCA writes/acquisition, tunable I2C register writes,
`setFir`, or NLC writes.

## Tests

Spy-driver tests prove:

- assembly and health/capabilities create no driver and perform no I/O;
- the complete capture is represented in one immutable B0;
- only approved queries/readbacks occur;
- no DCA write/acquisition, tunable I2C write, `setFir`, or NLC method is called;
- required VD1124 page-select writes are audited and restoration is verified;
- endpoint/profile, identity, source, status/units, channel, and pattern
  mismatches fail closed; and
- LIVE_TUNING factory requirements remain unchanged.
