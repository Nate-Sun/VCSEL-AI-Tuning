# V1.1 Optional Measurement Dataset Design

## Purpose

Add an opt-in, standardized measurement dataset bundle to V1.1 Sweep runs
without changing tuning algorithms, candidate authorization, hardware write
ordering, readback verification, rollback, or recovery behavior. Dataset
capture is disabled by default. A failure to capture or save dataset material
must never invalidate a successful TDECQ/Outer ER measurement or cause a
hardware rollback.

## Scope

This feature covers:

- an immutable `save_dataset: bool = false` campaign creation setting;
- a single recorder abstraction selected when a Sweep executor is assembled;
- complete FAKE/replay dataset capture and artifact verification;
- an explicit capability boundary for future audited LIVE DCA dataset capture;
- per-point standardized NPY, PNG, and JSON artifacts;
- API, JSON, and CSV evidence for measurement and dataset status;
- tests proving the existing B0 BERT values come from backend readback.

This feature does not add or guess FlexDCA SCPI commands, does not implement
Kimi or DINOv2, does not change FIR convolution, and does not change I2C,
`setFir`, NLC, FIR constraints, or rollback logic.

## Existing B0 Contract

`B0Snapshot` already stores the backend-captured BERT state as:

- exactly seven FIR taps;
- Upper NLC and Lower NLC;
- Pattern;
- BERT port;
- BERT channel.

The live/read-only gateway obtains these values from the BERT driver
configuration readback before constructing the snapshot. The implementation
will preserve this path and add contract tests at the snapshot and HTTP API
boundaries. No value may be populated from frontend `REFERENCE_FIR`, a GUI
cache, or a client request.

## Campaign Contract and Immutability

`CreateTaskRequest` gains a strict boolean field:

```python
save_dataset: StrictBool = False
```

The field is serialized into the existing immutable task payload, the
`TASK_CREATED` event, and the task configuration fingerprint. There is no API
that mutates task payload after creation. Runtime assembly reads the frozen
value from the persisted task when building the Sweep plan and executor.

The task detail response returns the persisted value. Older payloads that do
not contain the field are interpreted as `false` so existing databases remain
readable. The field is accepted for all V1.1 task types to support future AI
observation reuse, but this implementation records dataset bundles only for
Sweep points.

## Architecture

### Dataset recorder boundary

Create `src/vcsel_ai_tuning/v1_1/dataset.py` with the following focused types:

- `MeasurementStatus`: `SUCCESS`, `FAILED`, `REJECTED`;
- `DatasetStatus`: `DISABLED`, `COMPLETE`, `PARTIAL`, `FAILED`;
- `FrozenDatasetCapture`: immutable data returned by a dataset-capable DCA
  provider for one already completed acquisition;
- `MeasurementArtifactContext`: immutable campaign, point, parameter,
  measurement, B0, DCA, timing, and identity context;
- `DatasetOutcome`: JSON-safe status, paths, hashes, missing fields, and error;
- `DatasetRecorder`: one interface used by Sweep execution;
- `NoOpDatasetRecorder`: disabled implementation;
- `MeasurementArtifactBundleWriter`: enabled implementation.

The executor receives one recorder instance during assembly. No operation in
`SweepRunner`, candidate transactions, or hardware rollback branches checks
`save_dataset` directly.

### Frozen acquisition provider

The normal DCA `measure_single()` remains the only acquisition operation and
continues to produce the authoritative TDECQ and Outer ER measurement. The
executor assigns unique `measurement_id` and `acquisition_id` values around
that call.

After the acquisition is complete, the enabled recorder may invoke one lazy
read-only callback to obtain `FrozenDatasetCapture`. The callback is supplied
by an explicit dataset-capable adapter and must read only results frozen by
that acquisition. It must return the same `acquisition_id` and include source
identity sufficient to establish provenance.

`FrozenDatasetCapture` may contain:

- RLM;
- OMA;
- average power;
- equalizer taps and Main index;
- equalizer source/function;
- raw CHAN1A density matrix;
- raw CHAN1A eye image only when exported by the same acquisition;
- TDECQ equalized eye image;
- raw DCA responses and capture metadata.

The current production adapter has no audited density or image query/export
commands. Therefore the implementation will not invent any. In LIVE mode an
enabled recorder with no explicit provider returns `FAILED` dataset evidence
while leaving a valid primary measurement successful. FAKE/replay provides a
deterministic frozen capture and exercises the complete path.

### Same-acquisition rule

`dataset_status=COMPLETE` is allowed only when:

1. the primary measurement has a nonblank `acquisition_id`;
2. the frozen capture returns exactly the same `acquisition_id`;
3. required metrics, density, and distinct images are present and valid;
4. the density metadata describes the unchanged array;
5. all three data files are durably published and their hashes verified.

An ID mismatch, absent provider, missing field, invalid image, or incomplete
file set produces `PARTIAL` or `FAILED`. The recorder does not retry an
acquisition and never issues Stop, Clear, Single, source selection, I2C,
`setFir`, or NLC commands.

## Sweep Data Flow

For an accepted Sweep point:

1. existing authorization, candidate apply, and exact readback run unchanged;
2. existing settle delay runs unchanged;
3. the executor creates unique measurement and acquisition IDs;
4. existing `measure_single()` performs one controlled DCA acquisition;
5. TDECQ and Outer ER determine `measurement_status` exactly as today;
6. the recorder receives the point context and a lazy frozen-capture callback;
7. NoOp returns `DISABLED` without invoking the callback;
8. the writer invokes the callback once and publishes an artifact bundle;
9. dataset errors are converted to `DatasetOutcome`, never hardware errors;
10. the existing point record is persisted before restore as today;
11. existing B0 restore and recovery handling run unchanged.

A constraint-rejected point never reaches step 3 and therefore has no dataset
directory. A primary DCA failure produces `measurement_status=FAILED`; any
real partial capture already returned by the provider may be recorded, but no
placeholder data is generated.

## Artifact Layout and Atomicity

Each recorded point uses:

```text
<artifact_root>/
└── <campaign_id>/
    └── <sweep_point_id>/
        ├── record.json
        ├── raw_eye_density.npy
        ├── raw_eye.png
        └── tdecq_equalized_eye.png
```

The writer creates a unique sibling temporary directory, writes and flushes
each available file, calls `fsync` for durable evidence where supported, and
atomically renames the directory to its final name. A completed final
directory is never overwritten. Temporary directories are not presented as
completed samples.

If one data file fails after other genuine data was obtained, the writer
publishes the real files plus `record.json` with `dataset_status=PARTIAL` and a
missing-item list. If no data file can be published, the outcome is `FAILED`;
the error is still embedded in the Sweep point's existing raw/audit evidence.

## File Formats

### Density NPY

`raw_eye_density.npy` is written with `numpy.save` from a two-dimensional,
non-object ndarray. The writer does not flip, rotate, transpose, crop,
interpolate, normalize, or augment it. It records the exact `shape`, `dtype`,
and provider-declared `axis_order`. Tests reload it with
`numpy.load(..., allow_pickle=False)` and compare every element.

### Raw eye PNG

The preferred raw image is rendered deterministically from the unchanged
density matrix using a small standard PNG encoder. This avoids adding an image
dependency and ensures that the image contains only the raw CHAN1A eye. The
render maps finite density values monotonically to grayscale pixels without
geometric transformation. If a future audited provider supplies an exported
raw eye, it must carry the same acquisition ID and pass PNG validation.

### Equalized eye PNG

`tdecq_equalized_eye.png` must be supplied independently by the frozen capture
provider, must be a decodable PNG, and must carry the same acquisition ID. It
must not be byte-identical to `raw_eye.png`; an identical image is treated as
missing/invalid rather than accepted as equalized evidence.

SHA-256 is calculated only when dataset saving is enabled and only for the
three data files. `record.json` contains their relative paths, hashes, and
sizes. It does not recursively hash itself.

## record.json Contract

Every published record contains at least:

- schema version, campaign ID, and Sweep point ID;
- measurement ID and acquisition ID;
- UTC timestamp;
- requested, applied, and readback parameters;
- TDECQ, Outer ER, RLM, OMA, and average power;
- Outer ER query source;
- equalizer taps, Main index, and source/function;
- DCA configuration fingerprint and device identity;
- BERT port, channel, and Pattern from the frozen B0;
- `measurement_status` and `dataset_status`;
- dataset error and missing-item list;
- density shape, dtype, axis order, and source;
- relative paths, SHA-256, and sizes for the three data files;
- DCA acquisition duration and dataset file persistence duration.

The Sweep point payload/API/JSON/CSV additionally expose measurement ID,
acquisition ID, measurement status, dataset status, dataset error, and bundle
relative path. Existing requested/applied/readback, TDECQ, Outer ER, FIR,
error, rollback, timing, and terminal state fields remain unchanged.

## Status Semantics

`measurement_status` and `dataset_status` are independent:

- a valid primary measurement is `SUCCESS` even if dataset saving is
  `PARTIAL` or `FAILED`;
- a primary DCA failure is `FAILED`;
- a candidate rejected before hardware measurement is `REJECTED` and creates
  no point directory;
- disabled recording is always `DISABLED` and performs no dataset work;
- `COMPLETE` requires the full same-acquisition bundle;
- `PARTIAL` preserves at least one genuine data file but lacks another
  required item;
- `FAILED` means enabled capture/persistence produced no publishable dataset.

Dataset errors do not raise `HardwareTransactionError` or
`RecoveryRequired`, do not alter optimization validity, and do not request a
rollback. Existing hardware failures retain their current behavior.

## Compatibility and Persistence

No new database or framework is introduced. The task's existing JSON payload
stores the immutable switch. Sweep point evidence continues to use the
existing JSON payload column, so new fields are backward-compatible and older
records deserialize with disabled/absent dataset defaults.

The existing campaign-level `sweep_results.json` and `sweep_results.csv`
remain authoritative summaries. Per-point bundles are additional immutable
artifacts under the same configured artifact root.

## Security Boundaries

- Disabled mode performs no extra DCA query and no dataset hashing.
- A rejected candidate creates no dataset directory.
- Dataset capture never writes DCA configuration or starts another
  acquisition.
- Dataset code cannot access I2C or BERT mutation clients.
- Existing I2C RMW, BERT `setFir`, NLC, authorization, readback, rollback, and
  recovery code is unchanged.
- No random or placeholder hardware data is accepted.
- LIVE absence of an audited provider fails only the optional dataset.
- Existing completed point directories are never overwritten.

## Test Strategy

Contract tests will prove:

- `save_dataset` defaults to false, rejects non-booleans, persists in task
  payload/events/API, and cannot be mutated;
- legacy task payloads default to disabled;
- B0 snapshot/API values match fake BERT driver readback for taps, NLC,
  Pattern, port, and channel.

Recorder unit tests will prove:

- NoOp never invokes the lazy capture callback and creates no directory;
- a fixed replay capture produces exactly four files;
- NPY reload with `allow_pickle=False` exactly matches array, shape, and dtype;
- both PNGs decode and are distinct;
- all three SHA-256 values recompute exactly;
- measurement and acquisition IDs are internally consistent;
- acquisition mismatch cannot produce `COMPLETE`;
- one missing/failed file produces `PARTIAL` while retaining real files;
- persistence failure returns evidence rather than raising a hardware error;
- an existing destination is not overwritten.

Sweep integration tests will prove:

- disabled runs make zero additional DCA dataset calls;
- enabled replay runs publish one bundle per measured point before the next
  point begins;
- a dataset failure does not change a valid measurement, best-point selection,
  restore count, or final lifecycle;
- constraint-rejected points create no directory;
- API, database payload, `sweep_results.json`, and CSV report consistent IDs
  and statuses;
- no test imports or contacts real VISA, serial, or UDP drivers.

Targeted tests run before the complete Python suite. Frontend tests are needed
only if generated TypeScript contracts or task-creation UI fields are changed;
otherwise the HTTP contract tests are sufficient for this backend task.
