# VCSEL AI Tuning V1.2 Startup Guide / V1.2 启动指南

V1.2 uses one FastAPI process to serve both the API and the built frontend.
V1.2 使用一个 FastAPI 进程同时托管 API 和已构建的前端。

## Before startup / 启动前

From the V1.2 worktree, build the frontend once:
在 V1.2 worktree 中先构建一次前端：

```powershell
cd C:\Users\NateS\Documents\VCSEL\.worktrees\v1.2-integration
npm.cmd --prefix frontend install
npm.cmd --prefix frontend run build
```

## FAKE / 软件模拟

FAKE never opens DCA, I2C, or BERT connections. It is the default for UI,
workflow, optimization, and dataset-save acceptance.
FAKE 不会打开 DCA、I2C 或 BERT 连接，用于验收界面、流程、优化器和数据保存。

```powershell
.\start-v1.2.cmd -Mode FAKE -Port 8765
```

## READ_ONLY / 真实硬件只读

Review `configs/ai_tuning/runtime.v1.2.read-only.yaml` and the referenced
hardware profile before use. Starting the server does not run Preflight;
Preflight is a separate, explicit SOP step.
使用前必须复核 READ_ONLY 配置及其硬件 profile。启动服务不会自动执行
Preflight；Preflight 是后续独立且明确的 SOP 步骤。

```powershell
.\start-v1.2.cmd -Mode READ_ONLY `
  -ConfigPath .\configs\ai_tuning\runtime.v1.2.read-only.yaml `
  -Port 8765
```

## LIVE_TUNING / 真实硬件调参

Do not use LIVE_TUNING until READ_ONLY Preflight, one-point write/restore, and
the approved SOP have passed. The launcher only assembles the runtime;
hardware mutation still requires the backend authorization gates.
必须先通过 READ_ONLY Preflight、单点写入/恢复和已批准 SOP，才能使用
LIVE_TUNING。启动器只装配 runtime，硬件写入仍需通过后端授权门禁。

```powershell
.\start-v1.2.cmd -Mode LIVE_TUNING `
  -ConfigPath .\configs\ai_tuning\runtime.v1.2.live.yaml `
  -Port 8765
```

## Validation without hardware / 不连接硬件的配置验证

`-ValidateOnly` validates dependencies, paths, mode matching, storage access,
and port availability, then exits before starting FastAPI or contacting hardware.
`-ValidateOnly` 只验证依赖、路径、模式、存储写权限和端口，随后退出；不会启动
FastAPI，也不会连接硬件。

```powershell
.\start-v1.2.cmd -Mode READ_ONLY `
  -ConfigPath .\configs\ai_tuning\runtime.v1.2.read-only.yaml `
  -Port 8765 -ValidateOnly
```

The `.cmd` entry point applies `ExecutionPolicy Bypass` only to its child
PowerShell process, so it also works on PCs that block direct `.ps1` execution.
`.cmd` 入口只对它启动的 PowerShell 子进程使用 `ExecutionPolicy Bypass`，因此在
禁止直接执行 `.ps1` 的电脑上也能使用。

V1.2 runtime data is isolated under `state/v1.2` and `artifacts/v1.2`; it does
not reuse the frozen V1.1 SOP data.
V1.2 的运行数据独立保存在 `state/v1.2` 和 `artifacts/v1.2`，不会复用已冻结的
V1.1 SOP 数据。
